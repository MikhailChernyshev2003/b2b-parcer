# b2b-parcer

Парсер тендеров электронной торговой площадки [B2B-Center](https://www.b2b-center.ru/market/)
для **стороны поставщика**: автоматический сбор опубликованных процедур, сохранение в базу
и отбор подходящих по заданным критериям.

> **Важно про API.** Официальный веб-сервис B2B-Center (SOAP) предназначен для
> заказчиков/организаторов торгов и **не содержит** методов поиска чужих тендеров и подачи
> заявок. Поэтому сбор данных реализован через парсинг публичного раздела `/market/`.
> Сетевой слой вынесен в один модуль (`src/http/fetcher.ts`), чтобы при появлении доступа
> его можно было заменить на авторизованную сессию или Playwright без правки парсеров.

## Возможности

1. **Каркас** — TypeScript, SQLite (`better-sqlite3`), CLI.
2. **Сбор списка** процедур с `/market/` (фильтры: ключевые слова, статус, направление,
   даты) и сохранение в БД с дедупликацией.
3. **Карточка тендера** — детальный разбор (тип, организатор, регион, цена, валюта, сроки,
   условия оплаты/поставки, документация) + скачивание доступных файлов.
4. **Движок критериев** — отбор и скоринг тендеров по `config/criteria.yaml`, отчёт в
   консоль и в `data/report.{json,csv}`. Критерии включают:
   - ключевые слова, категории, регионы, типы процедур, цену, сроки;
   - **коды ОКПД2 / ОКВЭД** (совпадение по префиксу кода тендера);
   - **анализ содержимого документации** — извлечение текста из PDF/DOCX/TXT файлов тендера
     и отбор по словам «есть любое / есть все / стоп-слова».
5. **Авторизация** — Cookie сессии задаётся в UI (вкладка «Настройки») и применяется ко всем
   запросам; открывает документацию тендеров и постраничную навигацию.
6. **Планировщик** — периодический цикл (по умолчанию раз в 30 мин): сбор по ключевым словам
   из критериев → загрузка карточек новых тендеров → анализ документации → отбор; новые
   подходящие тендеры отмечаются.

Этапы 2–3 (AI-генерация документов заявки на основе документации компании, полуавтоподача
с ЭЦП) — последующие.

## Установка

```bash
npm install
cp config/criteria.example.yaml config/criteria.yaml   # отредактируйте под свою компанию
```

Требуется Node.js 20+.

## Использование

```bash
# Сбор списка. Без --keyword берёт ключевые слова из criteria.yaml.
npm run scrape -- --keyword "насосы,трубы"
npm run scrape -- --archive                 # искать в архиве
npm run scrape -- --date-from 01.06.2026 --date-to 10.06.2026   # нарезка по дням

# Детальные карточки.
npm run card -- --url "https://www.b2b-center.ru/market/.../tender-4492697/" --files
npm run card -- --limit 20 --files          # добрать карточки тендеров без деталей

# Отбор по критериям + отчёт.
npm run report -- --top 20

# Счётчики базы.
npm run stats

# Индексация уже скачанной документации (извлечь текст из файлов).
npm run index-docs -- --limit 100   # или: tsx src/index.ts index-docs

# Периодический мониторинг новых тендеров (для запуска на сервере).
tsx src/index.ts watch --interval 30   # цикл раз в 30 минут
tsx src/index.ts watch --once          # один цикл и выход

# Веб-интерфейс (фильтры, критерии, список тендеров, карточки, сбор, настройки).
npm run serve            # затем откройте http://localhost:5173
npm run serve -- --port 8080
```

## Веб-интерфейс

`npm run serve` поднимает локальный сайт с вкладками:

- **Тендеры** — фильтры (поиск, статус, сортировка, «только подходящие», «только с карточкой»),
  таблица со score-оценкой и панель подробностей по клику (все поля, доп. поля, статус анализа
  документации, причины совпадения, ссылка на B2B-Center, кнопка загрузки карточки).
- **Критерии** — редактор `config/criteria.yaml` со структурными полями, включая коды
  ОКПД2/ОКВЭД и критерии по содержимому документации; сохранение пересчитывает оценки.
- **Сбор** — запуск парсинга (ключевые слова, статус, направление, окно дат) и дозагрузка карточек
  с живым журналом задачи.
- **Настройки** — Cookie авторизованной сессии (с проверкой авторизации), параметры и управление
  планировщиком (интервал, запуск/остановка, прогон цикла сейчас, живой журнал и статус).

Задачи и циклы выполняются в фоне на сервере; интерфейс опрашивает их статус и показывает лог.

### Где взять Cookie авторизации

Войдите на B2B-Center в браузере → DevTools (F12) → вкладка **Application** (Приложение) →
**Cookies** → `https://www.b2b-center.ru` → выделите все строки (Cmd/Ctrl+A) и скопируйте →
вставьте в большое поле на вкладке «Настройки» и нажмите **«Распознать куки»**. Парсер
понимает табличный формат DevTools и строку `name=value; …`, автоматически убирает кавычки и
оставляет только куки домена `b2b-center.ru` (Яндекс/аналитика отфильтровываются). Затем
«Сохранить» и «Проверить авторизацию». Хранится локально в `data/settings.json`.

## Ограничение пагинации (гостевой режим)

Для неавторизованной сессии B2B-Center отдаёт только первые ~20 самых свежих совпадений и
**игнорирует номер страницы**. Поэтому охват достигается за счёт:

- множества узких запросов по ключевым словам (из `criteria.yaml`);
- нарезки по датам (`--date-from/--date-to`).

Если задать cookie авторизованной сессии (вкладка «Настройки» в UI или `B2B_AUTH_COOKIE`),
становится доступна постраничная навигация (`--pages N`) и **документация тендеров**. Без
авторизации файлы тендера обычно закрыты (в карточке проставляется флаг `requires_auth`), и
критерии по содержимому документации помечают такие тендеры как «документация не
проанализирована».

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `B2B_AUTH_COOKIE` | Cookie авторизованной сессии (включает пагинацию) | — |
| `B2B_REQUEST_DELAY_MS` | Задержка между запросами, мс | `1500` |
| `B2B_REQUEST_TIMEOUT_MS` | Таймаут запроса, мс | `40000` |
| `B2B_MAX_RETRIES` | Число повторов при сбое | `3` |
| `B2B_DB_PATH` | Путь к файлу SQLite | `data/tenders.sqlite` |
| `B2B_CRITERIA_PATH` | Путь к файлу критериев | `config/criteria.yaml` |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error` | `info` |

## Структура

```
src/
  index.ts              точка входа CLI
  cli.ts                разбор команд (scrape / card / report / stats / index-docs / watch / serve)
  config.ts             конфигурация и пути
  settings.ts           рантайм-настройки (cookie, интервал) -> data/settings.json
  scheduler.ts          периодический цикл сбор->карточки->документация->отбор
  types.ts              типы данных
  util.ts               утилиты (даты, очистка текста)
  http/fetcher.ts       единый HTTP-клиент (UA, динамический cookie, ретраи, троттлинг)
  db/db.ts              схема SQLite и операции
  scraper/
    searchParams.ts     построение URL поиска /market/
    listParser.ts       разбор таблицы результатов
    cardParser.ts       разбор карточки тендера
    marketScraper.ts    оркестрация сбора (+ нарезка по датам)
    cardScraper.ts      загрузка карточек и файлов (+ извлечение текста)
    docs.ts             извлечение текста из PDF/DOCX/TXT и индексация
  criteria/
    criteria.ts         загрузка/валидация/сохранение criteria.yaml (zod)
    matcher.ts          скоринг тендеров (вкл. коды ОКПД2/ОКВЭД и документацию)
    report.ts           отчёт (консоль + json/csv)
  server/
    server.ts           Express: REST API + раздача UI
    jobs.ts             фоновые задачи (сбор/дозагрузка/циклы) с журналом
public/                 веб-интерфейс (index.html, styles.css, app.js)
config/
  criteria.example.yaml пример критериев
data/                   БД, скачанные файлы и отчёты (в .gitignore)
```

## Правовые замечания

Парсинг публичных страниц и автоматизация — серая зона относительно правил площадки.
Соблюдайте вежливые задержки между запросами и при возможности запросите у куратора
B2B-Center официальный доступ/выгрузки для поставщика. Подача заявок на площадке требует
квалифицированной ЭЦП и выполняется с участием человека.
