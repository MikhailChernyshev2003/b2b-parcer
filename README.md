# b2b-parcer

Парсер тендеров электронной торговой площадки [B2B-Center](https://www.b2b-center.ru/market/)
для **стороны поставщика**: автоматический сбор опубликованных процедур, сохранение в базу
и отбор подходящих по заданным критериям.

> **Важно про API.** Официальный веб-сервис B2B-Center (SOAP) предназначен для
> заказчиков/организаторов торгов и **не содержит** методов поиска чужих тендеров и подачи
> заявок. Поэтому сбор данных идёт через те же внутренние JSON-эндпоинты, которыми
> пользуется сайт (см. «Как устроен сайт»), а классические карточки разбираются из HTML.
> Сетевой слой вынесен в один модуль (`src/http/fetcher.ts`).

## Быстрый старт

**Что нужно на компьютере**

- **Node.js 22** (подойдёт 20.16+ или 22.3+). Проверить: `node -v`. Если стоит
  [nvm](https://github.com/nvm-sh/nvm), достаточно `nvm install && nvm use` — версия берётся из `.nvmrc`.
- **Google Chrome** — через него выполняется вход на B2B-Center.
- **Git** и доступ к этому репозиторию на GitHub.
- Аккаунт на B2B-Center (свой или общий аккаунт компании).

**Установка**

```bash
git clone https://github.com/MikhailChernyshev2003/b2b-parcer.git
cd b2b-parcer
npm ci
```

Критерии отбора компании уже лежат в репозитории (`config/criteria.yaml`), копировать
пример не нужно.

**Первый запуск**

1. `npm start` и откройте http://localhost:5173.
2. Вкладка **«Настройки» → «Войти через браузер»**. В открывшемся окне Chrome войдите на
   B2B-Center (логин и пароль или электронная подпись) и отметьте «Запомнить меня». Окно
   закроется само, в шапке появится «авторизован».
3. Там же в блоке «Планировщик» нажмите **«Прогнать цикл сейчас»**. Первый цикл забирает всю
   ленту закупок (~6 500 тендеров, около 10 минут), отбирает подходящие и скачивает
   документацию для 50 лучших (остальные — в следующих циклах; сразу все:
   `npm run card -- --matched --files --limit 500`). Ход видно в журнале на вкладке «Сбор».
4. Вкладка **«Тендеры»** с фильтром «только подходящие» — результат. Чтобы лента обновлялась
   сама, нажмите «Запустить планировщик» (по умолчанию раз в 30 минут, пока открыт `npm start`).

**Что у каждого своё, а что общее**

- **Локально у каждого** (папка `data/`, в git не попадает): база тендеров, скачанная
  документация, cookie входа (`data/settings.json`), профиль браузера для входа. Базу коллеге
  передавать не нужно — она соберётся за первый цикл. Cookie и профиль браузера никому не
  пересылайте: это ваш вход на площадку.
- **Общее, через git**: код и критерии отбора `config/criteria.yaml`. Изменили критерии —
  закоммитьте их, чтобы у коллег отбор был таким же. Учтите, что сохранение критериев через
  веб-интерфейс перезаписывает файл без комментариев.

## Сервер

Парсер работает на сервере `178.17.50.107` в Docker-контейнере `b2b-parcer`: собирает ленту
по расписанию круглосуточно. **Из интернета он не открыт** — порт слушает только внутри
сервера, заходить нужно через SSH-туннель.

**Открыть интерфейс сервера**

```bash
ssh -N -L 5180:127.0.0.1:5180 root@178.17.50.107
```

Пока команда работает, интерфейс сервера доступен на http://localhost:5180 (порт 5180, чтобы
не путать с локальным запуском на 5173). Закрыть туннель — Ctrl+C.

**Вход на B2B-Center для сервера.** У сервера нет экрана для окна Chrome, поэтому входите на
своём компьютере и отправляйте cookie на сервер (туннель должен быть открыт):

```bash
npm run login -- --push http://localhost:5180
```

Делать это нужно, когда в шапке интерфейса сервера появится «cookie недействительна».

**Обновить сервер** до текущего закоммиченного состояния (образ собирается на сервере,
локальный Docker не нужен; остальные контейнеры сервера не затрагиваются):

```bash
deploy/deploy.sh              # выкатить HEAD
deploy/deploy.sh --rollback   # вернуть предыдущую версию
```

**Где данные.** База, документация, cookie и правки критериев лежат в Docker-томе
`b2b-parcer_b2b-data` и переживают обновления. Критерии из `config/criteria.yaml`
используются, пока их не сохранили через интерфейс сервера; после этого действует версия из
тома. Вернуться к версии из git: `ssh root@178.17.50.107 docker exec b2b-parcer rm /app/data/criteria.yaml`.

**Логи:** `ssh root@178.17.50.107 docker logs --tail 100 b2b-parcer`.

## Возможности

1. **Каркас** — TypeScript, SQLite (`better-sqlite3`), CLI.
2. **Сбор списка** процедур через API поиска (ключевые слова, статус, направление; даты,
   цена и страницы — только с авторизацией) и сохранение в БД с дедупликацией. Регион,
   категория и цена приходят сразу из списка.
3. **Карточка тендера** — детальный разбор (тип, организатор, регион, цена, валюта, сроки,
   условия оплаты/поставки, документация) + скачивание доступных файлов.
4. **Движок критериев** — отбор и скоринг тендеров по `config/criteria.yaml`, отчёт в
   консоль и в `data/report.{json,csv}`. Критерии включают:
   - ключевые слова, категории, регионы, типы процедур, цену, сроки;
   - **коды ОКПД2 / ОКВЭД** (совпадение по префиксу кода тендера);
   - **анализ содержимого документации** — извлечение текста из PDF, DOCX, XLSX, TXT/CSV/RTF
     файлов тендера и отбор по словам «есть любое / есть все / стоп-слова».
5. **Авторизация** — вход через окно Chrome (см. «Вход»); cookie проверяется на сайте, токен
   для нового приложения площадки получается автоматически.
6. **Планировщик** — периодический цикл (по умолчанию раз в 30 мин): проверка входа → сбор
   всей ленты новых закупок (без авторизации — по ключевым словам) → отбор → загрузка
   карточек и документации подходящих тендеров (лучшие первыми); новые подходящие
   тендеры отмечаются.
7. **Черновик заявки** — в карточке тендера форма с реквизитами и полями из документации,
   выгрузка в PDF.

Дальнейшие этапы (AI-генерация документов заявки на основе документации компании,
полуавтоподача с ЭЦП) — последующие.

## Использование

```bash
# Веб-интерфейс (всё ниже доступно и в нём).
npm start                # http://localhost:5173; другой порт: npm start -- --port 8080
npm run dev              # то же с перезапуском при правке кода

# Вход (окно Chrome; cookie сохранится сама).
npm run login

# Вся лента закупок до уже известных тендеров (нужна авторизация).
npm run scrape -- --feed

# Сбор по ключевым словам. Без --keyword берёт ключевые слова из criteria.yaml.
npm run scrape -- --keyword "насосы,трубы"
npm run scrape -- --archive                 # искать в архиве
npm run scrape -- --sell                    # продажи вместо закупок (--both-trades — оба)
npm run scrape -- --date-from 01.06.2026 --date-to 10.06.2026   # нарезка по дням (нужна авторизация поиска)

# Детальные карточки.
npm run card -- --url "https://www.b2b-center.ru/market/.../tender-4492697/" --files
npm run card -- --matched --files --limit 50 # карточки и документация подходящих, лучшие первыми
npm run card -- --limit 20 --files          # добрать карточки любых тендеров без деталей

# Отбор по критериям + отчёт.
npm run report -- --top 20

# Счётчики базы и проверка входа.
npm run stats

# Индексация уже скачанной документации (извлечь текст из файлов).
npm run index-docs -- --limit 100
npm run index-docs -- --all         # заново по всем скачанным файлам

# Периодический мониторинг без веб-интерфейса (например, на сервере).
npm run watch -- --interval 30   # цикл раз в 30 минут
npm run watch -- --once          # один цикл и выход

# Проверка типов (её же запускает CI на GitHub).
npm run typecheck
```

## Веб-интерфейс

`npm run serve` поднимает локальный сайт с вкладками:

- **Тендеры** — фильтры (поиск, статус, сортировка, «только подходящие», «только с карточкой»),
  таблица с оценкой и причиной отбора/отказа, панель подробностей по клику (все поля, статус
  документации, файлы, причины совпадения, ссылка на B2B-Center, загрузка карточки, черновик
  заявки).
- **Критерии** — редактор `config/criteria.yaml` со структурными полями, включая коды
  ОКПД2/ОКВЭД и критерии по содержимому документации; сохранение пересчитывает оценки.
- **Сбор** — запуск сбора (вся лента или ключевые слова, статус, направление, окно дат) и
  дозагрузка карточек с живым журналом задачи.
- **Настройки** — вход через браузер (и ручной ввод cookie), параметры и управление
  планировщиком (интервал, запуск/остановка, прогон цикла сейчас, живой журнал и статус).

Задачи и циклы выполняются в фоне на сервере; интерфейс опрашивает их статус и показывает лог.

### Вход

Вкладка «Настройки» → **«Войти через браузер»** (или `npm run login`). Откроется окно
Google Chrome со страницей входа B2B-Center. Войдите как обычно и отметьте «Запомнить меня».
Окно закроется само, cookie проверится и сохранится в `data/settings.json`. Пароль парсер не
видит. Профиль браузера хранится в `data/browser-profile`, поэтому, когда сессия истечёт,
планировщик сначала попробует восстановить её в фоне, без окна. Если не получится, в логе
появится просьба войти ещё раз.

Ручной способ (свёрнут в «Ввести cookie вручную»): войдите на B2B-Center в браузере →
DevTools (F12) → вкладка **Application** (Приложение) →
**Cookies** → `https://www.b2b-center.ru` → выделите все строки (Cmd/Ctrl+A) и скопируйте →
вставьте в большое поле на вкладке «Настройки» и нажмите **«Распознать куки»**. Парсер
понимает табличный формат DevTools и строку `name=value; …`, автоматически убирает кавычки и
оставляет только куки домена `b2b-center.ru` (Яндекс/аналитика отфильтровываются). Затем
«Сохранить» и «Проверить авторизацию». Хранится локально в `data/settings.json`.

## Как устроен сайт (по состоянию на октябрь 2026)

Осенью 2026 B2B-Center перевёл поиск на новое приложение: `/market/` редиректит на
`/app/next/market-search/`, старой таблицы результатов и параметра `f_keyword` больше нет.

| Что | Откуда берём |
| --- | --- |
| Список процедур | `GET /site/api/v1/market-search/?query=…&tab=actual&macro_trade_type=buy&page=…` (JSON) |
| Карточка нового типа (`/app/market-next/…/tender-N/`) | `POST /market/openapi/v2/trade/get_trade/` с `{"trade_id": N}` (JSON, работает и для гостя) |
| Карточка классического типа (`/market/…/tender-N/`) | HTML-страница карточки (`cardParser.ts`) |
| Проверка авторизации | `user_id` на `/market/view.html` (классика) и `user.id` в `/api/v1/config/` (новое приложение) |

Если сбор вернул 0 записей или карточка не распознана, это пишется в лог предупреждением:
обычно так проявляется очередное изменение сайта.

## Авторизация и режимы сбора

У сайта **две части с разной авторизацией**:

- **классическая** (старые страницы, классические карточки, их документация) работает по
  cookie сессии;
- **новое приложение** (поиск, карточки market-next, `/api/v1`) принимает только
  `Authorization: Bearer <токен>`. Парсер получает токен так же, как это делает сайт в
  браузере: тихий вход на OpenID-провайдере `/auth/openid/` по cookie сессии → одноразовый
  код → обмен на токен. Токен живёт 5 минут и обновляется автоматически.

С авторизацией API поиска отвечает `mode: "user"`: работают страницы и фильтры, поэтому
планировщик забирает **всю ленту закупок** (новые сверху) до уже известных тендеров, а
отбор делают критерии. Первый проход — около 6 400 тендеров (~9 минут), дальше несколько
секунд на цикл. Карточки и документация загружаются только для подходящих тендеров.

Без авторизации (`mode: "guest"`) поиск отдаёт только **первые 20 совпадений** на запрос и
игнорирует страницу, даты и цену. Тогда сбор идёт по ключевым словам из `criteria.yaml`,
а документация недоступна (флаг `requires_auth`).

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `B2B_AUTH_COOKIE` | Cookie авторизованной сессии | — |
| `B2B_OIDC_CLIENT_ID` | OpenID-клиент веб-приложения B2B-Center | клиент сайта |
| `B2B_REQUEST_DELAY_MS` | Задержка между запросами, мс | `1500` |
| `B2B_REQUEST_TIMEOUT_MS` | Таймаут запроса, мс | `40000` |
| `B2B_MAX_RETRIES` | Число повторов при сбое | `3` |
| `B2B_DB_PATH` | Путь к файлу SQLite | `data/tenders.sqlite` |
| `B2B_CRITERIA_PATH` | Путь к файлу критериев | `config/criteria.yaml` |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error` | `info` |

## Частые проблемы

- **`npm ci` падает на `better-sqlite3`.** Обычно это неподходящая версия Node: поставьте 22
  (`nvm install && nvm use`) и повторите. Если сборка всё равно идёт из исходников, нужны
  инструменты компиляции: на macOS `xcode-select --install`, на Windows — «Desktop development
  with C++» из Visual Studio Build Tools.
- **«Не удалось запустить Google Chrome».** Установите Chrome или войдите вручную через
  «Ввести cookie вручную» на вкладке «Настройки».
- **Порт 5173 занят.** `npm start -- --port 8080`.
- **В шапке «cookie недействительна» / «гость».** Сессия истекла — «Настройки» → «Войти через
  браузер». Без входа сбор работает, но только по 20 тендеров на ключевое слово и без
  документации.
- **В логе «Сбор не вернул ни одной записи» или «карточка не распознана».** Скорее всего,
  B2B-Center снова изменил сайт — нужна правка парсера (см. «Как устроен сайт»).
- **Документация «выдаётся только после регистрации на участие».** У классических тендеров
  файлы открываются кнопкой «Скачать документацию», которая регистрирует компанию на
  участие; автоматически парсер этого не делает.

## Правовые замечания

Парсинг публичных страниц и автоматизация — серая зона относительно правил площадки.
Соблюдайте вежливые задержки между запросами и при возможности запросите у куратора
B2B-Center официальный доступ/выгрузки для поставщика. Подача заявок на площадке требует
квалифицированной ЭЦП и выполняется с участием человека.
